## 当前管理员界面的真实布局问题

### 1. 固定 238px 高度在小分辨率已越界

`AdminRoleCardScreen.init()`（第 21 行）固定 `top=Math.max(3,(height-238)/2)`，而 `render()`（第 25 行）始终绘制到 `top+238`：

- **320×240**：`left=10`、`top=3`，面板底部为 `241`，已越过屏幕 1px；底部按钮在 `y=217..237`，距底边仅 3px。
- **427×240**：`left=6`、`w=415`、`top=3`，面板同样到底 `241`，左右安全边距只有 6px，不满足建议的约 8px，也会把操作区推向其他模组 HUD 的边缘。
- **854×480 / 1920×1080**：宽度永远封顶 440px，虽不会越界，但内容仍由 238px 的单一压缩表单承载，不能利用空间建立分区或阅读生平。

因此不能只调 `top` 或按钮坐标；应由纯布局模型根据安全边距、最大宽度、可用高度和是否需要滚动共同计算标题、摘要、主体、退回区与底栏。

### 2. 文本与控件存在实际叠层

第 25 行先绘制标签，随后 `super.render(...)` 才绘制所有 `EditBox`。例如名称标签位于 `top+52`，名称输入框覆盖 `top+47..65`；年龄、性别标签及全部六维标签也分别落在其输入框的纵向范围内。结果是标签被后绘制的控件遮挡或与其混在一起，而不是“标签在输入框上方”。

生平说明在 `top+84`，输入框从 `top+94` 开始，未直接重叠，但它明确写着“单行编辑”；完整生平既不能以多行阅读，也没有可见的滚动、字数或边界提示。退回原因框 `top+192..210` 与操作按钮 `top+214..234` 之间仅 4px，进一步压缩了主体。

### 3. 视觉体系与信息层级缺失

- 面板只是两块 `fill` 的深蓝矩形（第 25 行），没有主/次边框、分区、切角、输入焦点、禁用、危险操作等一致状态。
- 标题只有“管理角色卡：原版名”，摘要只有“状态 + 版本”。没有 UUID 摘要、角色名/原版名的明确区分，也没有状态徽章和语义颜色。
- “剩余点数”、六维输入和审核操作全挤在同一表单；六维为 3×2 的极窄纯数字框，缺少当前含义、属性增益摘要、可读的标签与校验状态。
- 所有主要按钮均为原版灰石 `Button`，宽度 45px，保存、批准、退回、解锁没有危险性/主次视觉区分；管理员没有显式“关闭”操作，只有 Esc 兜底。
- `approve` / `reject` / `unlock` 始终可点击，即使当前状态不允许，失败后仅聊天消息；退回原因也始终可编辑，无法提示何时会被使用。

### 4. 表单可用性、无障碍与反馈不足

- `box(...)` 给每个 `EditBox` 传入 `Component.empty()`（第 22 行），没有可供旁白识别的字段名称；当前按钮只有原版默认旁白，输入字段语义不足。
- 保存数值解析失败被静默吞掉（第 23 行）；服务端拒绝、revision 冲突、权限失败、目标离线和非法状态都只走聊天消息。需要在面板内显示短暂、可消失的成功/警告/错误反馈，且不能伪造服务端成功。
- 当前直接使用默认输入框外观；已锁定/不可执行操作没有禁用皮肤、原因 tooltip 或键盘焦点状态。管理员可编辑范围虽与服务端权限不同，但审核动作仍必须按状态明确禁用并说明原因。
- `reason` 客户端限制 160 字符，而审核包允许 640 字节；这不是服务端安全问题，却会让 UI 规则与协议容量不一致。重构时应明确产品限制与字数/字节提示，并保持不超过协议限制。

## 建议的管理员线框（与玩家共用体系）

```text
安全边距
┌────────────────────────── 档案面板 ──────────────────────────┐
│ 管理员审核 · 角色档案             [待审核 徽章] [修订 #12]    │
│ 原版名 Steve · UUID 12345678…abcd                              │
├──────────────────── 档案内容 / 可裁剪或滚动 ──────────────────┤
│ [身份] 名称（主字段）                                          │
│        年龄                性别                                │
│ [生平] 有边框的多行阅读/编辑区，内边距、滚动条、字数            │
│ [六维] 紧凑属性卡（名称、数值、增益摘要、数值编辑）              │
│ [点数] 剩余点数徽章                                             │
│ [退回] 原因输入区（仅退回可用；独立于主体高度）                 │
├───────────────────────────────────────────────────────────────┤
│ [关闭（次要）]          [保存调整（中性）] [退回（警告）] [批准]│
│ 面板内反馈：保存成功 / revision 已变化，请刷新后重试            │
└───────────────────────────────────────────────────────────────┘
```

小屏优先缩减横向列数（身份年龄/性别和六维转单列），不缩小字体；主体超过可用高度时只滚动主体，标题与底栏固定。玩家页签可由同一“分段页签”组件提供，管理员若不拆页也应复用内容分区、字段、属性卡、底栏和反馈条。

## 可复用实现点

1. **保留原生行为层**：继续以 `AbstractButton`/`Button`、`EditBox` 为输入、Tab 焦点和旁白基础，外层只统一自绘皮肤与可访问名称；不要引入外部 UI 库。
2. **统一 token 与绘制层**：集中定义安全边距（约 8px）、面板/内层/输入背景、主次边框、正文/弱化/标题/强调文字和成功/警告/错误色；提供面板、切角边框、徽章、字段框、反馈条和 tooltip 安全定位辅助方法。
3. **复用现有多行能力但补齐裁剪**：`MultiLineBiographyBox` 已提供按宽换行和滚轮入口，可在统一的档案文本控件中补上边框、内边距、滚动条、光标/选区裁剪和只读阅读模式，供玩家与管理员使用。
4. **复用现有网络边界**：`OpenAdminCardPacket` 的目标 UUID、原版名和卡片 NBT 是正确的只读输入。成功后重新打开管理员屏幕也可作为刷新路径；失败反馈应由服务端明确回执/客户端反馈桥接驱动，而不是根据“已发包”猜测成功。
5. **抽出无 Minecraft 依赖的布局模型**：例如 `RoleCardLayout` / `ArchiveLayout` 返回不可变矩形和列数。Screen 只将模型映射为 Widget 与 `GuiGraphics`，避免再散落 `top+...`、`w-...` 和颜色常量。

## 测试与 CI 探针扩展建议

### 纯布局自动测试（本次必须补）

对玩家与管理员的布局模型分别在 **320×240、427×240、854×480、1920×1080** 运行断言：

- 每一个可点击矩形都位于安全区，宽高不为负；关键步进器至少 20×20；
- 标题/摘要、页签、内容说明、字段、退回原因、反馈条和底栏互不相交；页签下缘与说明文字之间存在稳定间距；
- 底栏绝不覆盖内容，窄屏转单列/启用主体滚动而非压缩字号；
- 管理员状态分别为草稿、待审核、已批准、已退回时，批准/退回/解锁的可用性、原因区与禁用原因符合状态机；
- 计算结果可在不创建 `Minecraft`、`Font`、网络或真实 Screen 的情况下运行，作为快速 CI 单测/纯逻辑门禁。

### 真实客户端探针（可行且不虚报像素美观）

当前 `ClientSmokeProbe`（第 37–55 行）只观察 `TitleScreen`。在保留其“稳定后正常退出”语义的前提下，可增加一个有限状态序列：构造最小 `CompoundTag` 后依次 `setScreen` 为玩家身份页、生平页、六维页和 `AdminRoleCardScreen`，每页等待若干稳定 tick，记录屏幕类别、布局模型中的矩形、Widget 边界和无异常证据；页面切换只调用本地 UI 路径，不能点击会发 C2S 的保存/审核按钮。

Xvfb 脚本当前固定 1280×720（`client-smoke.sh` 第 18 行），因此它只能证明该实际窗口的初始化、切页和稳定 tick；四种分辨率的“不重叠/不越界”必须由上述纯布局测试覆盖。日志和文档必须明确：自动检查**不等价于像素级美观、真实鼠标命中、旁白体验或整合包 HUD 兼容性**。

## 建议验收重点

1. 在 320×240 与 427×240、常见 GUI Scale 下实机打开审核面板，确认右侧 HUD 存在时标题、状态、退回区和底栏都仍在安全区内。
2. 以待审核、已批准、已退回三种卡分别验证按钮禁用、原因输入、成功/失败/revision 冲突的面板内反馈，以及 Esc/关闭、Tab 焦点和旁白。
3. 填写长生平与长退回原因，确认多行阅读、滚动、字数、边框、光标和文字均不越界；再用在线目标的真实审核会话验证服务端重开/回执后的刷新。
