# v1.2.1 紧急修复执行记录

## 目标

修复管理员新增任务目标时的客户端崩溃，并将玩家档案与管理员任务界面收敛到同一套响应式布局规则；补上真实控件交互回归和发布核验。

## 执行顺序

1. 完整审计界面、任务 DTO／网络／持久化与现有 GitHub Actions 探针，保留异常堆栈和首个根因证据。
2. 以纯函数布局输出表单字段、文本基线、目标行与底栏矩形，替换手写分散坐标。
3. 目标编辑改为稳定行列表；新增、删除、切换和保存均不重建整个 Screen。
4. CI 在真实 Forge/Xvfb 客户端走 Widget 点击、文本输入、滚动、切换与保存触发路径，输出控件矩形 JSON；网络/SavedData 边界另由逻辑探针验证。
5. 仅在 Hosted Runner 的质量门禁、构建、专服、客户端和回归报告全部成功后，核验唯一 Jar 并发布 `v1.2.1`。

## 已定位根因

原 `AdminMissionScreen` 在删除目标后仍保留删除前的 `selectedObjective`。删除最后一项时，随后的选择函数先按这个旧索引回写缩短后的 `ArrayList`，因此触发 `IndexOutOfBoundsException`；删除中间项时，同一回写顺序还可能以旧编辑框内容覆盖已前移的下一项。新增空目标本身不是首个异常，用户的“新增—编辑—删除／再新增”真实路径才会触发它。

修复不吞异常：目标行在初始化时一次性创建，删除前提交各行，删除后只移动数据、刷新槽位和隐藏尾部控件。服务端仍对权限、revision、字段类型、长度和目标上限做权威拒绝，客户端通过面板反馈显示拒绝原因。

## 自动与人工验收边界

自动探针覆盖真实 Forge 客户端中的 Widget 点击、中文／ASCII 输入、完成开关、删除中间及最后项、再新增、12 项上限、滚动、保存按钮、快照 DTO 校验和客户端任务／编辑器回包 Hook；布局探针输出五种分辨率的控件矩形 JSON。它不能判断字体像素美观、Tooltip 边缘、第三方 HUD、不同 GUI Scale，也不等同于真实多人连接中的 C2S→服务端→S2C 时序；发布后须由复测人员完成这些项。

## 保护项

- `docs/发布v1.1.0核验记录.md` 为用户未跟踪文件：不修改、不删除、不暂存、不提交。
- 本机不运行 Gradle、Java、Forge 或 Minecraft；动态验证仅在 GitHub Hosted Runner。
