# 使用与扩展说明

## 安装与侧别

1. 使用 Java 17 和 Forge `1.20.1-47.4.10`。
2. 将同一个构建 Jar 放进客户端与服务器的 `mods` 目录。
3. 首次启动服务端后编辑 `world/serverconfig/rolecard-server.toml`，重启服务器或使用 Forge 配置重载流程。

客户端只负责界面、输入和显示缓存；专用服务器保存角色卡、核算点数、控制状态流转和应用属性。`common` 代码不得静态引用客户端 Screen，管理员打开面板使用明确的服务端至客户端数据包。

## 玩家完整流程

1. 管理员用 `/rolecard points set|add` 向玩家发放可分配点数。
2. 玩家按默认键 **I** 打开居中“角色档案册”，在身份、生平、六维页填写同一份草案；小屏保留安全边距，六维可在内容区滚动。
3. 生平可换行与滚动编辑，界面显示字数；服务器默认最大 1500 字符，拒绝控制字符、格式字符、超长字符串和不安全组件文本。
4. 在六维页用 `+` / `-` 调整壮硕、力量、协调、反应、精神、幸运。界面显示服务器同步的当前值、草案变化、剩余点数和按“当前值加草案变化”计算的鼠标悬停属性预览。
5. 点击“提交角色卡”后，服务器以当前发送者、当前状态、当前修订号和自身保存的点数重新校验；成功后变为 `PENDING`。
6. 管理员批准则锁定为 `APPROVED`；退回则为 `REJECTED`，玩家会收到原因并可修改后重提（默认允许）。

客户端不保存权威点数，也不能指定目标 UUID、总预算、状态或审核结果。重开界面、重连或重放旧网络包不会复制点数或覆盖较新卡片。

### 状态机与默认规则

```text
DRAFT ──提交──> PENDING ──批准──> APPROVED
  ^                │                  │
  └──退回/解锁──── REJECTED <──管理员退回/解锁──┘
                    │
                    └──修改后提交──> PENDING
```

- `DRAFT`：玩家可自由编辑，未提交的点数调整只在本卡草案内生效。
- `PENDING`：默认锁定，防止管理员查看的内容被玩家在审核中替换。服主可将 `allowDraftEditsWhilePending` 设为 `true`；服务器仍逐次核算并更新修订号。
- `APPROVED`：默认锁定身份、生平和六维，玩家不能自行洗点；管理员可批准、退回、解锁或直接调整。
- `REJECTED`：默认允许编辑；若 `allowRejectedEdits=false`，须由管理员解锁。
- 同一张待审核卡再次提交只更新已有待审记录，不增加重复队列项。玩家离线后卡和待审核索引仍持久化。

## 管理员审核与命令

所有修改、审核和指定玩家操作要求原版权限等级 2。参数补全给出在线玩家和六维键；网络管理操作还会验证发送者权限、目标在线状态、状态迁移和数据修订号。

```text
/rolecard card [玩家]
/rolecard identity set <玩家> <年龄> <性别> <角色名称...>
/rolecard stat set <玩家> <六维键> <数值>
/rolecard stat add <玩家> <六维键> <增量>
/rolecard stat reset <玩家>
/rolecard reset <玩家>

/rolecard points set <玩家> <数值>
/rolecard points add <玩家> <数值>
/rolecard review list
/rolecard review open <玩家>
/rolecard review approve <玩家>
/rolecard review reject <玩家> [原因...]
/rolecard review unlock <玩家>
```

`points set/add` 调整的是服务器保存的剩余可分配点数；`stat set/add/reset` 是管理员直接编辑最终六维。两者刻意分开，避免把管理员补正误算为玩家可凭空消费的点数。

玩家提交时，所有在线权限等级 2 管理员会收到包含原版名、角色名、提交时间与状态的醒目可点击通知；点击会执行简化的 `review open` 入口。管理员登录也会提示当前持久化待审数量。`review list` 始终可查看索引；管理面板现阶段面向在线目标，离线目标应等待上线后使用 `open`，不把“可列出”误写成“可离线强开客户端界面”。

审核面板使用资料、六维、审核分区，显示原版名、UUID 摘要、身份、生平、六维、剩余点数、状态、退回原因与修订号；可批准、退回（简短原因）或调整后保存。即便由面板发起，服务端也不会信任 DTO：只接受受控字段，并以服务器中该 UUID 的最新数据为准。

六维摘要与 tooltip 使用客户端语言：优先沿用 Minecraft 属性翻译，中文和英文资源提供稳定兜底；普通界面只显示友好名称，按住 Shift 才显示 ResourceLocation/description id 等高级标识。固定增益显示数值，乘法增益显示百分比；管理员编辑框中的未保存值也会即时预览。

## 显示与配置

配置文件为 `world/serverconfig/rolecard-server.toml`：

```toml
[display]
showOverheadRoleName = true
showChatRoleName = true
tabNameMode = "ROLE"

[workflow]
maxBiographyLength = 1500
allowDraftEditsWhilePending = false
allowRejectedEdits = true
```

- `showOverheadRoleName`：显示头顶角色名，不修改 GameProfile。
- `showChatRoleName`：装饰聊天发送者名。
- `tabNameMode`：`VANILLA`（原版名）、`ROLE`（角色名，默认）、`HIDDEN`（空名称组件，保留条目）。
- `maxBiographyLength`：生平最大字符数。应保持在网络包上限以内；修改后新提交立即按服务端值验证。
- `allowDraftEditsWhilePending`：是否允许待审核卡继续编辑，默认 `false`。
- `allowRejectedEdits`：是否允许被退回的卡自行编辑，默认 `true`。

本模组不改账号真名、UUID、白名单、封禁、选择器或命令身份。其他模组若也改显示名事件，最终显示取决于 Forge 事件顺序，须在目标整合包实测。

## 数据、迁移与网络安全

每位玩家的 Capability `rolecard:card` 写入玩家 NBT。数据版本从 v1.0.0 的 `1` 升级为 `2`，字段扩展为：身份、六维、生平 `biography`、剩余点数 `availablePoints`、审核状态、退回原因和递增 `revision`。读取 v1 及缺字段 NBT 时：

- 原有身份和六维按原值读取（超范围值仍钳制到 0–100）；
- 新字段使用安全默认值，不丢失旧资料；含旧六维数值的卡默认标为 `APPROVED` 并锁定，避免升级后把原管理员数值撤回为可用点数；全零六维旧卡为可编辑草稿；
- 字符串执行长度、UTF-8 与安全文本清洗；损坏字段不会使登录失败；
- 每次成功更新递增修订号。提交、保存、批准、退回包必须带匹配修订号，冲突时拒绝并回传最新卡。

登录、死亡重生、跨维度、重连都会复制或重算卡片、应用属性并同步给本人。属性应用只先移除本模组稳定 UUID 的 Modifier，再添加新的永久 Modifier，不累积、不覆盖其他模组；最大生命降低时会钳制当前生命。

所有 C2S/S2C 包固定注册方向并限制字符串与集合长度。C2S 包以 `packet sender` 而非客户端目标为准；管理包额外验证权限等级 2、目标在线、合法状态迁移及最新 revision。公共逻辑不依赖客户端类，专服可以安全加载。

## 属性映射扩展

`AttributeMappings` 是集中定义层。每条 `AttributeRule` 包含目标 Attribute、`AttributeModifier.Operation`、系数、数值上限、启用开关和稳定文本生成的 UUID。新增映射时为对应 `StatType` 添加类似：

```java
AttributeRule.of("稳定键", () -> Attributes.XXX, operation, coefficient, cap)
```

稳定键发布后不要改动，避免历史 Modifier 无法清理。当前映射：

| 六维 | 原版属性 |
| --- | --- |
| 壮硕 | 最大生命、护甲、击退抗性 |
| 力量 | 攻击伤害、攻击击退 |
| 协调 | 移动速度 |
| 反应 | 攻击速度、移动速度 |
| 精神 | 护甲韧性、少量幸运 |
| 幸运 | 幸运 |

显示层由 `AttributeDisplayFormatter` 集中处理，不要在新的 Screen 中截断 `getDescriptionId()` 或拼接技术键。新增第三方 Attribute 时可在 `assets/rolecard/lang/zh_cn.json` 与 `en_us.json` 维护 `rolecard.attribute.name.<命名空间>.<路径>` 兜底键；若不存在，界面会友好化名称但只在 Shift 高级 tooltip 暴露标识。

## 已知边界与人工验收

- 审核通知只发给当前在线管理员；离线管理员依靠持久化待审索引和登录提示。当前管理面板需要目标在线，离线资料的完整可视化不是本版范围。
- UI 使用原生 `Screen`/`GuiGraphics`，不引入外部 UI 库；仍需在 320×240、常见 GUI Scale 和高分辨率实测多行编辑、滚动、按钮状态与文本可读性。
- CI 覆盖迁移、文本、状态、修订、权限与属性等可控逻辑；真实双客户端通知点击、审核交互、死亡 clone、重连、换维和与其他属性/名称模组叠加仍需人工验证。

构建结果与完整清单见 [`构建与验证`](构建与验证.md) 和 [`持续集成与验证矩阵`](持续集成与验证矩阵.md)。
