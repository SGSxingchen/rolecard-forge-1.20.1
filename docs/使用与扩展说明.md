# 使用与扩展说明

## 安装

1. 使用 Java 17 和 Forge `1.20.1-47.4.10`。
2. 将构建得到的 `build/libs/rolecard-1.0.0.jar` 放入客户端与服务器的 `mods` 目录。
3. 首次启动服务端后编辑 `world/serverconfig/rolecard-server.toml`，再重启或使用 Forge 配置重载流程。

客户端只提供界面，不保存权威数据；专用服务器也必须安装本模组。

## 玩家操作

- 按默认键 **I** 打开“角色档案”。键位可在控制设置的“角色卡与六维”分类中修改。
- 可编辑角色名称、年龄（0–999）和性别；点击“确认保存”后，服务器会重新验证、持久化并回传结果。
- 名称和性别最长 32 个字符，禁止格式及控制字符。空角色名称会回退显示原版游戏名；32 个中文字符可安全同步。
- 六维默认由管理员管理；界面会显示数值、鼠标悬停可查看当前映射的实际属性增益。

## 显示与配置

服务端配置文件 `world/serverconfig/rolecard-server.toml`：

- `showOverheadRoleName`：开关头顶角色名称。实现仅改变 Forge 显示组件，**不改 GameProfile**。
- `showChatRoleName`：开关聊天发送者名称装饰。实现使用 Forge 的玩家显示名格式事件，因此与同样改写显示名的模组需按整合包实测事件顺序。
- `tabNameMode`：`VANILLA`（原版名）、`ROLE`（角色名，默认）、`HIDDEN`（空显示组件）。隐藏模式不从玩家列表删除条目，避免破坏网络列表同步。
本模组不改账号真名、UUID、白名单、封禁、选择器或命令身份。其他模组若也改同一显示事件，最终展示取决于事件优先级；本模组不尝试覆盖其 Profile 或 AttributeModifier。

## 管理员命令

所有修改命令要求原版权限等级 2；参数会提供玩家和六维键建议。

```text
/rolecard card [玩家]                 查看自己的卡；管理员可查看指定玩家
/rolecard identity set <玩家> <年龄> <性别> <角色名称...>
/rolecard stat set <玩家> <六维键> <数值>
/rolecard stat add <玩家> <六维键> <增量>
/rolecard stat reset <玩家>           只重置六维
/rolecard reset <玩家>                重置整张角色卡
```

六维键为：`bulk`（壮硕）、`strength`（力量）、`coordination`（协调）、`reflex`（反应）、`spirit`（精神）、`luck`（幸运）。数值会限制为 0–100；`set` 的命令输入范围为 -100–100（实际保存时仍会钳制到 0–100），`add` 使用该范围增减。

## 数据与生命周期

每位玩家的 Capability `rolecard:card` 写入玩家 NBT，数据版本为 `1`。字段包括 `roleName`、`age`、`gender` 和 `stats`。缺键、旧档和超范围数值均会安全回退/钳制，不把可编辑数据与真实 UUID 或游戏名混写。

登录、死亡重生、跨维度都会复制或重算数据、应用属性并向本人同步。身份编辑包仅由客户端发起意图、服务端以 packet sender 为准验证；不会信任客户端的目标玩家或计算结果。客户端至服务端和服务端至客户端的包均固定收发方向。登出时 Capability 随玩家持久化生命周期自动写回。

## 属性映射扩展

`AttributeMappings` 是集中定义层。每条 `AttributeRule` 都包含：目标 Attribute、`AttributeModifier.Operation`、系数、数值上限、启用开关和由稳定文本生成的 UUID。应用时仅先移除本模组自己的 UUID，再添加新的永久 modifier，因此不会累积、覆盖或清空其他模组的修正；最大生命下降后会钳制当前生命。

第一版映射只引用 1.20.1 确实存在的原版属性：

| 六维 | Attribute |
| --- | --- |
| 壮硕 | 最大生命、护甲、击退抗性 |
| 力量 | 攻击伤害、攻击击退 |
| 协调 | 移动速度 |
| 反应 | 攻击速度、移动速度 |
| 精神 | 护甲韧性、少量幸运 |
| 幸运 | 幸运 |

新增映射时在该类为对应 `StatType` 添加 `AttributeRule.of("稳定键", () -> Attributes.XXX, operation, coefficient, cap)`。稳定键一经发布不要改动，避免遗留 UUID 无法清理。1.20.1 没有合适的原版“游泳/实体交互”独立 Attribute，因此本版没有硬引用它们。

## 已知限制与人工验收

- UI 当前只同步自身完整身份和六维，避免把年龄/性别广播给其他客户端；服务器事件负责公共显示。
- 聊天、Tab、头顶若被另一模组同阶段重写，需按整合包实际事件优先级验证。
- 需要人工验证：专服启动；两客户端联机时三类名称显示；死亡重生；退出重连；跨维度；属性装备叠加；权限等级 0/2 的命令与伪造编辑包拒绝情况；以及 320×240 与常用高分辨率下的界面布局。

构建结果、静态检查和可执行人工测试清单见 [`构建与验证`](构建与验证.md)。
