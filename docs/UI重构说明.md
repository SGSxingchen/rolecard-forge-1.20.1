# v1.1.1 UI 重构说明（含 v1.1.2 属性显示修复）

> 本文在改代码前根据 `RoleCardScreen`、`AdminRoleCardScreen` 与生平编辑控件的完整审查编写；
> 本次只调整客户端呈现和交互适配，不改变存档、网络包、服务端权限、审核状态机或点数语义。

## 已确认的问题

- 原玩家面板固定高 238 像素，在 320×240 时会越过安全区；页签与其后的说明文字实际重叠，六维末行、锁定提示、反馈与底栏也会互相压住。
- 标题、状态、点数和修订号混在同一条顶栏；六维的手写 16×15 点击区没有键盘焦点、禁用态或旁白支持。
- 原版灰石按钮与深蓝矩形混用，字段、底栏、生平框都没有统一边界和层级。生平框缺裁剪、滚动条和可见光标。
- 管理员界面把身份、生平、点数、六维、退回原因和四个操作硬塞在 238 像素内，生平还是单行输入，无法安全阅读或编辑长文本。

## 统一视觉与控件规则

界面使用“角色档案册”而不是原版灰石按钮：墨黑蓝内容底、蓝灰主边框、低对比内分隔、暖白标题、浅灰正文、灰蓝弱化文字；青蓝用于焦点/可编辑强调，绿/琥珀/红分别表示成功、警告/待处理、错误/危险。基础间距为 **8 px**，紧凑间距为 4 px，控件高度至少 20 px；面板使用像素切角和双层描边。

| 状态 | 徽章颜色 | 玩家表现 |
| --- | --- | --- |
| 草稿 | 灰蓝 | 可填写、可保存、可提交 |
| 待审核 | 琥珀 | 默认阅读锁定，显示等待说明 |
| 已批准 | 绿色 | 阅读锁定，显示批准说明 |
| 已退回 | 红色 | 显示原因；按服务器规则允许时可重新编辑 |

按钮、页签、步进器都有 normal、hover、focused、disabled、pressed 皮肤；仍继承原生
`AbstractButton` 行为，保留 Tab 导航和旁白。禁用的提交按钮提供原因 tooltip。反馈在面板底部操作栏上方显示短句，成功/警告/错误按色区分，且不覆盖控件。

## 玩家界面线框

```text
安全边距
┌ 角色档案 ───────────────────── [状态徽章] [修订号] ┐
│ [身份] [生平] [六维]                                  │
│ ┌ 内容区（页签以下固定间距）─────────────────────────┐ │
│ │ 身份：名称；年龄/性别并排；字段说明或锁定阅读视图  │ │
│ │ 生平：多行阅读/编辑框、可见边框、滚动条、字数      │ │
│ │ 六维：页首 [剩余 N 点]，响应式属性卡与 - 数值 +    │ │
│ └──────────────────────────────────────────────────┘ │
│ 反馈/锁定或退回提示                                    │
│ [关闭]                         [保存草稿] [提交角色卡] │
└──────────────────────────────────────────────────────┘
```

- 标题左置；状态和修订号右置，点数只在六维页首显示。
- 面板居中，最大宽度有限，四周至少保留 8 px 安全边距，不把关键控件贴向其他模组 HUD。
- 六维在有足够宽度时两列；小屏自动单列并在内容视窗内滚动。每项展示名称、当前/拟调整值、简短增益摘要和至少 20×20 的 `− 数值 +` 原生可聚焦步进器；摘要和 tooltip 都按当前值加草案变化预览。
- 属性显示统一由客户端格式化层处理：优先使用原版 Attribute 翻译，缺失时用角色卡中英语言资源兜底；固定值和百分比分别显示，不在普通卡片中出现内部 snake_case。完整 tooltip 通过原生多行 API 绘制并自动避让屏幕边缘；按住 Shift 才追加高级标识。
- 身份只读时改为标签—值阅读排版并移除输入外观。生平只读时同样改为裁剪的阅读视图。

## 管理员审核界面线框

```text
┌ 审核档案 ───── 玩家原版名 / UUID 摘要 ─ [状态] [修订] ┐
│ [资料] [六维] [审核]                                    │
│ 内容区：资料页为身份与可滚动生平；六维页可调整点数/属性 │
│ 审核页为状态说明、退回原因多行框与风险提示               │
│ 反馈                                                     │
│ [关闭]                 [保存调整] [退回] [批准/解锁]    │
└────────────────────────────────────────────────────────┘
```

管理员复用同一 token、面板、字段和按钮，也复用玩家的属性格式化层并以编辑框数值预览增益。保存调整为强调色；批准为成功色；退回为危险色；解锁为警告色。退回原因独占审核页内容区，不能挤压主体资料；仍由服务器二次验权和验 revision。

## 布局与自动验证边界

以纯 `ArchiveLayout` 模型计算安全区、标题、页签、内容、反馈、底栏和属性卡矩形。自动断言
320×240、427×240、854×480、1920×1080：矩形在安全区内、页签不压说明、内容不压底栏、交互矩形至少 20×20 且彼此不相交。客户端探针还会打开玩家四页、管理员角色卡三页和管理员任务四页，检查初始化、页切换、控件边界和稳定 tick。

这些检查会初始化六维 tooltip 组件，但不能判断字体换行、真实 HUD、tooltip 避让的像素美观；它们仍需在 Forge 客户端人工验收。

## v1.2.0 世界任务页与管理页

玩家档案第四页复用档案册面板、页签、徽章和内容裁剪：顶部为任务状态徽章，副本信息以紧凑信息格显示，简介、目标、规则和备注在同一阅读视窗滚动；已完成目标弱化但仍可读。未发布时只显示居中的空状态，不渲染空白大面板。管理员任务管理器也复用同一 `ArchiveLayout` 与 `ArchiveUi`，以基础、简介、目标、规则/备注四页容纳多行编辑、字数和错误反馈，适配最小 320×240。
