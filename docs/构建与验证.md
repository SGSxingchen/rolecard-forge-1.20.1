# 构建与验证

## 执行边界

本项目的真实构建、Forge 专服启动和 Forge 客户端启动由 GitHub Actions 的 GitHub Hosted Runner 完成。本地环境只用于 Git、文本/YAML/Python 静态检查和 `gh` 查询；**不得**在本机运行 `gradle`、`gradlew`、Java、Forge 或 Minecraft 动态测试。

历史 `build/` 目录仅供排查参考，不是本次 CI 产物，也不能证明当前提交已通过验证。

## CI 构建

推送或拉取请求会触发 [持续集成工作流](../.github/workflows/ci.yml)。Hosted Runner 使用 Java 17 执行：

```text
./gradlew clean build --no-daemon
```

工作流只上传一个可发布 Jar，并排除 sources、javadoc、dev、plain 和测试探针 Jar。随后检查 Jar 内的 `META-INF/mods.toml` 与 `modId="rolecard"`，生成 SHA-256 清单。详见[持续集成与验证矩阵](持续集成与验证矩阵.md)。

## 验证范围

- 必需自动验证：静态质量门禁、Java 17 构建、真实 Forge 专服加载与命令基础调用、真实 Forge 客户端初始化/主菜单冒烟。
- 不可虚报为已自动覆盖：死亡 clone、重连、换维、恶意网络包、权限拒绝、属性重复累积的完整运行期场景，以及两客户端显示和 UI 交互。
- 每次运行以 `regression-report` 为准：任一必需 Job 失败、被跳过或缺失，整次验证即为失败。

## 人工验证清单

1. 使用同一 CI 发布 Jar 启动 Forge 1.20.1 / 47.4.10 专服，并让两名客户端加入。
2. 以权限等级 0 与 2 分别验证 `/rolecard` 的拒绝和成功；再检查超范围、控制字符、未知六维及伪造编辑请求均不能越权修改数据。
3. 依次验证头顶、聊天、Tab 原版名/角色名/隐藏三种服务端配置，以及两名客户端观察到的显示是否一致。
4. 验证死亡重生、退出重连、主世界/下界/末地换维后卡数据、属性、生命值和同步结果。
5. 与装备、药水及目标整合包中的其他属性模组叠加，反复修改六维后确认 Modifier 不累积。
6. 在 320×240 与常用高分辨率中操作角色界面，确认编辑、提示和按钮可用。

联网、数据库、网页展示、跨任务世界与道具继承均不在本版本实现范围，边界见 [未来同步设计](未来同步设计.md)。
