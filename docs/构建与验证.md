# 构建与验证

## 本地构建

在项目根目录使用 Java 17 兼容工具链执行：

```bash
./gradlew build --no-daemon
```

产物为 `build/libs/rolecard-1.0.0.jar`。构建过程会从 ForgeGradle 缓存下载 Minecraft 1.20.1 与 Forge 47.4.10 所需依赖。

本工程已于 2026-08-04 执行该命令并得到 `BUILD SUCCESSFUL`；Gradle 的测试任务显示 `NO-SOURCE`，因此以下人工联机项目仍不可省略。

## 已覆盖的静态检查

- 编译、资源处理、Jar 重混淆和 `build` 任务均须成功。
- 数据读取会回退并钳制异常 NBT；身份文本不允许格式或控制字符。
- 网络包区分客户端至服务端和服务端至客户端方向，服务端只按实际发送者修改身份。
- Capability 在附加、克隆、登录、重生、换维时保持数据并重施加属性；属性修正以稳定 UUID 先删后加，最大生命降低时夹当前生命。
- 客户端 UI 不会由专用服务器类加载，并将卡片压缩至 320×240 的常见最小窗口范围内。

## 必须人工验证的边界

1. 使用相同 Jar 启动 Forge 1.20.1 专用服务器，并用两名客户端加入。
2. 创建和修改角色名称、年龄、性别；使用权限等级 0 与 2 分别验证命令拒绝和成功。
3. 依次验证头顶、聊天名称、Tab 原名/角色名/隐藏三种服务端配置，并在配置重载后确认在线玩家刷新。
4. 验证死亡重生、末地回城、退出重连和跨维度后，卡数据、属性和生命值均正确。
5. 与装备、药水及其他属性模组叠加，重复登录和修改六维后确认没有重复 Modifier。
6. 在 320×240 与常用高分辨率中打开界面，确认字段、提示与两个按钮均可操作。
7. 用抓包或测试客户端发送超范围年龄、控制字符、未知六维和反向方向数据包，确认服务器拒绝且不改变他人或自身的未授权数据。

联网、数据库、网页展示、跨任务世界与道具继承均不在本版本实现范围，边界见 `未来同步设计.md`。
