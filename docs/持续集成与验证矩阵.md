# 持续集成与验证矩阵

> **执行边界**：真实 Gradle、Java、Forge、Minecraft 客户端、专用服务器和逻辑测试只在 GitHub Actions 的 GitHub Hosted Runner 运行。本地只允许 Git、文本、YAML、Python 静态检查及 GitHub CLI 查询；历史 `build/` 文件不是 CI 结果，不能作为发布或通过依据。

## 触发与总览

工作流文件为 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)。它在推送 `main`、拉取请求与手动触发时运行。`regression-report` 必须依赖所有必需 Job，并拒绝任一失败、跳过或缺失结果。

| Job | 运行环境 | 目的 |
| --- | --- | --- |
| `quality-gates`（含 v1.1.0/v1.1.2 逻辑探针） | Hosted Runner（静态/Python） | 资源、元数据、侧别、网络注册、依赖、CI 文件、角色卡规则与属性显示契约门禁。 |
| `build` | Hosted Runner / Java 17 | `clean build`，筛选唯一发布 Jar 并校验内容与 SHA-256。 |
| `dedicated-server` | Hosted Runner / Java 17 | 安装固定 Forge 专服，加载本次 Jar 并作真实启动与基础命令验证。 |
| `client-smoke` | Hosted Runner / Java 17 / Xvfb + Mesa | 启动真实 Forge 客户端，确认完成稳定初始化后正常退出。 |
| `regression-report` | Hosted Runner | 汇总上述必需 Job、日志与本文件定义的覆盖矩阵。 |

工作流不使用 `continue-on-error` 伪造成功。Forge 安装器和关键下载固定 Minecraft `1.20.1`、Forge `47.4.10`；下载失败仅允许有限重试，关键文件应做存在性和 SHA-256 校验。CI 不创建 tag 或 Release。

## 静态质量门禁

`quality-gates` 检查本模组特有边界：

- 资源路径小写，JSON、TOML 与 `pack.mcmeta` 可解析；modid、版本、Minecraft/Forge 版本一致；
- 公共/服务端侧不得直接引用 `net.minecraft.client` 或 `com.rolecard.client`，避免专服类加载失败；
- 网络包注册编号不重复、方向明确；客户端意图由实际 sender 决定，管理操作有服务端权限与 revision 校验入口；
- 角色卡版本 2、状态机、文本/包长度限制、稳定属性 UUID 及待审索引去重规则存在；
- Gradle Wrapper、CI 脚本、发布包筛选与 Forge 安装关键文件完整。

静态检查只能提前发现结构问题，不代替运行时加载、网络会话或 GUI 操作。

## 逻辑探针

逻辑测试不得依赖真实客户端输入，也不得进入发布 Jar。它可采用 JUnit、纯 Java 测试源集或仅 CI 临时 Forge 探针，但必须在 Hosted Runner 运行并输出可下载日志。最少覆盖：

- v1 NBT 迁移、缺字段/损坏数据容错及版本 2 默认值；
- 生平边界、换行/Unicode、安全字符过滤与 UTF-8/网络长度上限；
- `availablePoints` 点数守恒、每项 0–100、管理员直接调整与玩家消费的职责隔离；
- 伪造预算、目标 UUID、过期 revision、重复/重放提交的拒绝；
- `DRAFT`、`PENDING`、`APPROVED`、`REJECTED` 的合法/非法迁移，重复 pending 的队列幂等；
- 权限等级不足的审核/管理拒绝；
- 属性 Modifier 反复应用不重复、不删除其他来源修正。
- 九项原版属性的中英文兜底、固定值/百分比/正负零格式、草案预览、多行 tooltip、普通界面无内部键，以及 Shift 高级标识边界。

## 构建产物与真实运行

`build` 以 Java 17 运行 `./gradlew clean build --no-daemon`，只选择一个可发布模组 Jar。`*-sources.jar`、`*-javadoc.jar`、`*-dev.jar`、`*-plain.jar` 与测试探针不得作为发布产物。工作流断言 Jar 含 `META-INF/mods.toml` 与 `modId="rolecard"`，并上传发布 Jar、SHA-256 清单和构建日志。

`dedicated-server` 将本次 Jar 放入新安装 Forge 专服的 `mods` 目录，写入 EULA 后启动，等待完成标志，确认 `rolecard` 加载，执行基础命令和 `save-all flush` 后正常停止。日志不得有 FATAL、`NoClassDefFoundError`、客户端类泄漏、Mixin 错误或 crash-report。

`client-smoke` 在 Xvfb/Mesa 软件渲染下启动真实 Forge Client。仅 CI 源集探针可拷入 `run/mods`；发布 Jar 校验必须拒绝探针。探针优先确认 TitleScreen 稳定 40 tick，否则连续 200 个真实 Client tick 后正常退出。它证明客户端可初始化，不等价于多人 UI 交互验收。

## 覆盖矩阵

下表描述 CI 能提供的证据能力，**不表示某一提交已经通过**。只有 Actions 中对应 commit 的全部必需 Job 成功，才可称本次 CI 全绿。

| 验证目标 | CI 判定 | 证据/边界 |
| --- | --- | --- |
| Java 17 构建、发布 Jar 元数据与 SHA-256 | 完整自动覆盖 | `build` 的 Gradle、Jar 与清单断言。 |
| 资源、mod 元数据、公共侧客户端引用、网络注册 | 完整自动覆盖（静态） | `quality-gates`；不替代加载测试。 |
| v1 迁移、生平边界、点数守恒、状态机、revision、幂等、权限、属性不重复 | 完整自动覆盖（逻辑） | `quality-gates` 内的 v1.1.0 CI 逻辑探针可重复断言。 |
| 属性名称兜底、数值/百分比格式、草案预览、多行 tooltip 与普通界面防技术键泄漏 | 完整自动覆盖（静态/逻辑） | v1.1.2 属性显示探针检查中英文资源和 UI/formatter 契约。 |
| 专服加载、命令注册和基础调用 | 完整自动覆盖 | `dedicated-server` 启动与控制台日志。 |
| Forge 客户端稳定初始化、角色卡四页/审核三页/任务管理四页构造切换 | 部分自动覆盖 | `client-smoke` 的 Xvfb/Mesa 真客户端探针检查初始化、页签切换、几何关系、六维 tooltip 初始化和稳定 tick；不判断像素美观。 |
| 任务 SavedData 边界、revision、权限、命令、同步与广播入口 | 完整自动覆盖（静态/逻辑） | v1.2.0 任务公告探针校验 DTO 限制、世界级持久化、服务入口、包方向、OP2 与旧包防护；不替代真实多人时序。 |
| 恶意网络包穿过真实会话后的拒绝 | 部分覆盖 | 逻辑/静态覆盖校验分支；真实恶意客户端注入仍需专用会话。 |
| Clone、重连、跨维度后数据/属性同步 | 部分覆盖 | 逻辑规则可测；完整 Forge 生命周期须人工或稳定专用会话。 |
| 在线通知点击、管理员管理面板与多页编辑 | 人工待测 | 真客户端的点击、GUI Scale 与网络时序不由 smoke 操作。 |
| 两客户端名称显示与其他名称/属性模组兼容 | 人工待测 | 需目标整合包和双客户端实测。 |
| 离线审核管理员登录提示、离线玩家后续上线审核 | 人工待测 | 需跨会话持久化与登录时序实测。 |

## 故障诊断与复跑

1. 在 Actions 页面打开失败的 commit 对应 run，下载同名日志工件；不要以本地 `build/` 或旧 run 判断。
2. `quality-gates` 失败：按报错修复路径大小写、版本、侧别、包方向/注册或安全边界，不能跳过门禁。
3. v1.1.0 逻辑探针失败：先定位迁移、文本、点数、状态或 revision 的具体断言；禁止删测或弱化断言来求绿。
4. `build`、专服或客户端失败：依次检查 Gradle、`latest.log`、crash-reports、Forge 安装器和 CI 探针日志；专服出现客户端类泄漏必须先修复侧别。
5. 修复后提交并推送 main 或手动重跑；仅当 `regression-report` 报告所有必需 Job 成功，才可汇报 CI 全绿。
