## CI 说明

每次推送和拉取请求都会在 GitHub Hosted Runner 运行分层 CI：静态质量门禁、Java 17 构建、真实 Forge 专用服务器启动，以及 Xvfb + Mesa 下的真实 Forge 客户端冒烟。构建会上传唯一可发布 Jar、构建日志、SHA-256 清单及运行日志；不会自动创建 Release。

本仓库不在本机运行 Gradle、Java、Forge 或 Minecraft 动态测试。本地 `build/` 历史文件不能视为 CI 通过证据。两客户端显示、UI 操作、生命周期恢复和整合包兼容性仍须按[人工验证清单](docs/构建与验证.md#人工验证清单)执行。

> GitHub 仓库创建并首次 CI 成功后，再补入指向实际仓库的 Actions 状态徽章；在此之前不展示占位或虚假的通过状态。
